# Main Entry Point: main.py

## Overview
Primary CLI entry point for the Template-Based Page Generator v2. Contains a single `TemplateBasedGeneratorCLI` class that orchestrates page generation operations.

## Method Call Order

### Parent Page Creation Flow
| Order | Method | Called From |
|-------|--------|-------------|
| 1 | `main()` | CLI entry |
| 2 | `argparse.ArgumentParser.parse_args()` | main() |
| 3 | `TemplateBasedGeneratorCLI.__init__()` | main() |
| 4 | `create_parent_page()` | main() (if args.command == 'parent') |
| 5 | `project_detector.detect_capabilities()` | create_parent_page() |
| 6 | `PageConfig(name=name)` | create_parent_page() |
| 7 | `GenerationContext(config, capabilities, frontend_root, variables)` | create_parent_page() |
| 8 | `TemplateFileReferencer(template_engine.static_dir)` | create_parent_page() |
| 9 | `referencer.get_all_dependencies(["App.tsx.template", "main.tsx.template"])` | create_parent_page() |
| 10 | `dependency_manager.validate_and_create_root_files()` | create_parent_page() |
| 11 | `dependency_manager.ensure_styles_directory()` | create_parent_page() |
| 12 | `dependency_manager.ensure_all_dependencies()` | create_parent_page() |
| 13 | `parent_generator.create_parent_page()` | create_parent_page() |
| 14 | `parent_generator.validate_parent_creation()` | create_parent_page() |
| 15 | `_print_validation_results()` | create_parent_page() |
| 16 | **Navigation files generated by DependencyManager** | create_parent_page() |

### Child Page Creation Flow
| Order | Method | Called From | Condition |
|-------|--------|-------------|-----------|
| 1 | `main()` | CLI entry | Always |
| 2 | `argparse.ArgumentParser.parse_args()` | main() | Always (parses --mobile flag) |

| 7 | `create_parent_page()` | create_child_page() | Only if parent doesn't exist |
| 8 | `PageConfig(name=name, parent=parent, mobile=mobile)` | create_child_page() | Always |
| 9 | `GenerationContext(config, capabilities, frontend_root, variables)` | create_child_page() | Always |
| 10 | `TemplateFileReferencer(template_engine.static_dir)` | create_child_page() | Always |
| 11 | `referencer.get_all_dependencies(["App.tsx.template", "main.tsx.template"])` | create_child_page() | Always |
| 12 | `dependency_manager.validate_and_create_root_files()` | create_child_page() | Always |
| 13 | `dependency_manager.ensure_styles_directory()` | create_child_page() | Always |
| 14 | `dependency_manager.ensure_all_dependencies()` | create_child_page() | Always |
| 15 | `child_generator.create_child_page(context)` | create_child_page() | Always |
| 16 | `_update_parent_for_new_child()` | create_child_page() | Always |

| 19 | `_print_validation_results()` | create_child_page() | Always |
| 20 | **Navigation files generated by DependencyManager** | create_child_page() | Always |

### Analysis Flow
| Order | Method | Called From |

| 2 | `argparse.ArgumentParser.parse_args()` | main() |

### Core Generation Methods

#### create_parent_page(name: str)
**Parameters:** `name` - Parent page name
**Purpose:** Creates complete parent page with supporting files
**Calls:** 
- `project_detector.detect_capabilities()` - Detect project capabilities
- `PageConfig(name=name)` - Create page configuration
- `GenerationContext(config, capabilities, frontend_root, variables)` - Create generation context
- `TemplateFileReferencer(template_engine.static_dir)` - Initialize template referencer
- `referencer.get_all_dependencies(["App.tsx.template", "main.tsx.template"])` - Find template dependencies
- `dependency_manager.validate_and_create_root_files(context, force)` - Create missing root files
- `dependency_manager.ensure_styles_directory(context, force)` - Copy styles
- `dependency_manager.ensure_all_dependencies(context, all_dependencies)` - Create static dependencies
- `parent_generator.create_parent_page(context)` - Generate parent page files
- `parent_generator.validate_parent_creation(context)` - Validate generation
- `_register_parent_and_update_navigation(config)` - Update navigation

#### create_child_page(name: str, parent: str, mobile: bool = False)
**Parameters:** 
- `name` - Child page name
- `parent` - Parent page name  
- `mobile` - Whether to create mobile variant
**Purpose:** Creates child page with adaptive wrapper selection
**Calls:**
- `project_detector.detect_capabilities()` - Detect project capabilities
- `project_detector.check_parent_exists(parent)` - Check if parent exists
- `create_parent_page(parent)` - Auto-create parent if missing
- `PageConfig(name=name, parent=parent, mobile=mobile)` - Create page configuration
- `GenerationContext(config, capabilities, frontend_root, variables)` - Create generation context
- `TemplateFileReferencer(template_engine.static_dir)` - Initialize template referencer
- `referencer.get_all_dependencies(["App.tsx.template", "main.tsx.template"])` - Find dependencies
- `dependency_manager.validate_and_create_root_files(context, force)` - Create root files
- `dependency_manager.ensure_styles_directory(context, force)` - Copy styles
- `dependency_manager.ensure_all_dependencies(context, all_dependencies)` - Create static dependencies
- `child_generator.create_child_page(context)` - Generate child page files
- `_update_parent_for_new_child(context, name)` - Update parent routing
- `dependency_manager.regenerate_index_files(frontend_root)` - Regenerate index files
- `child_generator.validate_child_creation(context)` - Validate generation
- `_register_child_and_update_navigation(config)` - Update navigation

### Navigation Integration (Now Handled by DependencyManager)

Navigation generation has been integrated directly into the DependencyManager workflow during the `ensure_static_components()` phase. Navigation files are now created dynamically using NavigationGenerator instead of static templates, eliminating the override issue.

## Lessons Learned

### Questions Answered from Code Analysis:

**✅ What is the EXACT order of operations during page creation?**
- Complete execution order is now documented in the flow tables above
- Parent creation: 17 distinct steps from CLI entry to navigation generation
- Child creation: 21 distinct steps including conditional parent creation

**✅ How does the navigation generation integration actually get called?**
- Step 12: `dependency_manager.ensure_all_dependencies()` calls `ensure_static_components()`
- Within `ensure_static_components()`: Navigation files are detected and routed to `_create_navigation_files_dynamically()`
- Navigation generation now runs during dependency creation, not after page generation

**✅ When does dependency scanning happen vs dependency creation?**
- Step 8-9: `TemplateFileReferencer` scans dependencies starting from core templates
- Step 10-12: `DependencyManager` validates, copies styles, and ensures all dependencies exist
- Scanning happens before any file generation, creation happens immediately after

**✅ Where in the flow do static templates actually get written to disk?**
- Step 12: `dependency_manager.ensure_all_dependencies()` writes static templates to disk
- This happens BEFORE page generation and BEFORE navigation generation

**✅ How does the `regenerate_index_files()` call fit into this?**
- Step 17 (child flow only): Called after parent routing update but before validation
- Only runs in child creation flow, not parent creation flow

### Key Architectural Insights:

**Template Processing Order:**
1. Navigation files created dynamically during `ensure_static_components()` via NavigationGenerator
2. Regular static templates created via `ensure_static_components()` 
3. Page-specific files generated via `parent_generator` or `child_generator`

**Mobile Page Handling:**
- Mobile flag parsed in step 2 via `argparse`
- Stored in `PageConfig` in step 8 (child flow)
- Used by `child_generator.create_child_page()` in step 15 to determine file generation

**Error Handling Pattern:**
- Each major operation wrapped in try/except blocks
- Validation occurs after generation with `_print_validation_results()`
- Navigation generation errors handled in DependencyManager with fallback to static templates
